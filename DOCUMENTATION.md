## Project Overview

**DecisionGraveyard** is an Android application that helps users track their decisions over time and evaluate their outcomes later. The core concept is that users "bury" decisions with a scheduled review date, then later evaluate whether the decision was good, bad, or neutral. This creates a feedback loop for decision-making patterns.

### Key Features
- **Decision Tracking**: Log decisions with title, description, category, and scheduled review date
- **Delayed Evaluation**: Decisions are "locked" until the review date
- **Outcome Assessment**: Evaluate decisions as good, bad, or neutral with reflection notes
- **Analytics**: View decision quality scores, category-based regret rates, and time-of-day patterns
- **Risk Assessment**: Visual feedback based on historical decision patterns
- **Notifications**: Reminders when decisions are ready for review
- **Export**: Export decision history to CSV
- **Theme Support**: Dark and light mode
- **Google Sign-In**: Authenticate with Google account for seamless login
- **Activity Tracking**: Schedule and track activities with completion status
- **Pattern Detection**: Automatic detection of missed activity patterns
- **Recovery Missions**: Structured missions to break negative patterns
- **AI-Powered Insights**: Personalized insights generated by Google Gemini API
- **Pre-Miss Reminders**: Notifications 10 minutes before activity deadlines
- **WorkManager Integration**: Background periodic checks for pattern analysis

## Architecture

The project follows **MVVM (Model-View-ViewModel)** architecture with a clean separation of concerns:

```
┌─────────────────┐
│     UI Layer    │
│  (Activities/   │
│   Fragments)    │
└────────┬────────┘
         │ LiveData
┌────────▼────────┐
│ ViewModel Layer │
│  (Business      │
│   Logic)        │
└────────┬────────┘
         │
┌────────▼────────┐
│  Repository     │
│  (Data Access)  │
└────────┬────────┘
         │
┌────────▼────────┐
│  Data Layer     │
│  (Firebase      │
│   Firestore)    │
└─────────────────┘
```

### Architecture Principles
- **Unidirectional Data Flow**: User input → ViewModel → Repository → Data → Repository → ViewModel → UI
- **Reactive Updates**: LiveData and Firestore snapshot listeners for real-time updates
- **Separation of Concerns**: Each layer has a single responsibility
- **Repository Pattern**: Centralized data access abstraction

## Data Layer

### Models

#### Decision.java
Core decision entity representing a logged decision.

**Properties**:
- `id` (long): Unique identifier
- `title` (String): Decision title
- `description` (String): Detailed description
- `category` (String): Category (money, health, study, personal, work, relationship)
- `decisionTime` (long): When decision was made (timestamp)
- `evaluationTime` (long): When evaluation is scheduled (timestamp)
- `decisionHour` (int): Hour of day (0-23)
- `userId` (String): Firebase user ID
- `outcome` (String): Evaluation result (good/bad/neutral)
- `reflectionNotes` (String): User's reflection notes
- `evaluatedAt` (Long): Timestamp of evaluation

**Key Methods**:
- Multiple constructors for different use cases
- Standard getters/setters for all properties
- `toString()`: String representation for debugging

#### Evaluation.java
Stores evaluation results for decisions.

**Properties**:
- `id` (long): Unique identifier
- `decisionId` (long): Reference to decision
- `outcome` (String): good/bad/neutral
- `reflectionNotes` (String): User's thoughts
- `evaluatedAt` (long): Timestamp of evaluation

#### DecisionRecord.java
Combines Decision and Evaluation into a single object.

**Properties**:
- `decision` (Decision): The decision object
- `evaluation` (Evaluation): The evaluation object (nullable if not evaluated)

**Key Methods**:
- `isEvaluated()`: Returns true if evaluation exists
- `isReadyForReview()`: Returns true if current time >= evaluation time
- `isUpcoming()`: Returns true if not evaluated and not ready
- `getOutcomeOrPending()`: Returns outcome or "pending"

#### User.java
Firebase user document stored in Firestore.

**Properties**:
- `userId` (String): Firebase auth UID
- `email` (String): User email
- `createdAt` (Timestamp): Account creation timestamp

#### CategoryInsight.java
Analytics data for decision categories.

**Properties**:
- `category` (String): Category name
- `evaluatedCount` (int): Total evaluated decisions in category
- `regretCount` (int): Number of bad decisions
- `regretRate` (int): Percentage of regrets (0-100)

#### AnalyticsSnapshot.java
Comprehensive analytics snapshot.

**Properties**:
- `totalDecisions` (int): Total number of decisions
- `totalEvaluated` (int): Number of evaluated decisions
- `goodCount` (int): Number of good decisions
- `badCount` (int): Number of bad decisions
- `neutralCount` (int): Number of neutral decisions
- `readyForReviewCount` (int): Decisions ready for review
- `upcomingCount` (int): Decisions not yet ready
- `categoryInsights` (List<CategoryInsight>): Category-based analytics
- `generatedInsights` (List<String>): Textual insights

**Key Methods**:
- `isEmpty()`: Returns true if no evaluations exist
- `getGoodPercent()`: Percentage of good decisions
- `getBadPercent()`: Percentage of bad decisions
- `getNeutralPercent()`: Percentage of neutral decisions
- `getQualityScore()`: Overall decision quality score (0-100)

#### Activity.java
Activity tracking entity for scheduled tasks and commitments.

**Properties**:
- `activityId` (long): Unique identifier
- `title` (String): Activity title
- `category` (String): Category classification
- `scheduledTime` (long): When activity is scheduled (timestamp)
- `completed` (boolean): Completion status
- `completedTime` (Long): Timestamp when completed (nullable)
- `userId` (String): Firebase user ID
- `createdAt` (long): Creation timestamp

**Key Methods**:
- `getStatus()`: Returns status based on state
  - "completed": If marked as completed
  - "missed": If past scheduled time and not completed
  - "pending": If future time and not completed

#### PatternTracker.java
Analyzes activity completion patterns to detect failure trends.

**Properties**:
- `consecutiveMisses` (List<String>): List of consecutively missed activity titles
- `totalMisses` (int): Total missed activities in analysis period
- `mostMissedCategory` (String): Category with most misses
- `isPatternDetected` (boolean): Whether a concerning pattern exists
- `patternMessage` (String): Human-readable pattern description
- `recoveryActivitiesNeeded` (int): Number of activities to complete for recovery

**Key Methods**:
- Builder pattern for flexible construction
- Pattern detection logic (3+ consecutive misses triggers pattern)
- Recovery activity calculation

#### RecoveryMission.java
Represents a recovery mission to break negative patterns.

**Properties**:
- `missionId` (String): Unique mission identifier
- `title` (String): Mission title
- `description` (String): Mission description
- `activitiesToComplete` (int): Target activity count
- `activitiesCompleted` (int): Completed activity count
- `deadline` (long): Mission deadline timestamp
- `isCompleted` (boolean): Mission completion status
- `userId` (String): Firebase user ID

**Key Methods**:
- `getProgress()`: Returns completion percentage (0.0-1.0)
- `isExpired()`: Returns true if deadline passed and not completed
- Builder pattern for construction

### Database Layer

#### DatabaseHelper.java
SQLite database helper (legacy, Firebase Firestore is primary data store).

**Database Schema**:
```sql
CREATE TABLE decisions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    description TEXT,
    category TEXT NOT NULL,
    decision_time INTEGER NOT NULL,
    evaluation_time INTEGER NOT NULL,
    decision_hour INTEGER NOT NULL
)

CREATE TABLE evaluations (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    decision_id INTEGER NOT NULL UNIQUE,
    outcome TEXT NOT NULL,
    reflection_notes TEXT,
    evaluated_at INTEGER NOT NULL,
    FOREIGN KEY(decision_id) REFERENCES decisions(id) ON DELETE CASCADE
)
```

**Key Methods**:
- `insertDecision(Decision)`: Insert new decision
- `upsertEvaluation(Evaluation)`: Insert or update evaluation
- `deleteDecision(long)`: Delete decision (cascades to evaluations)
- `hasSimilarDecision(String, String, long)`: Check for duplicates in 24-hour window
- `getAllDecisionRecords()`: Get all decisions with evaluations
- `getDecisionRecord(long)`: Get single decision by ID
- `getPendingDecisions()`: Get unevaluated decisions

## Repository Layer

### DecisionRepository.java
Central data access layer using Firebase Firestore. Implements the Repository pattern to abstract data operations.

**Interfaces**:
```java
interface DecisionRecordsListener {
    void onChanged(@NonNull List<DecisionRecord> records);
    void onError(@NonNull String message);
}

interface ActionCallback {
    void onSuccess();
    void onError(String error);
}
```

**Key Methods**:

#### Decision Management
- `createDecision(long, String, String, String, long, ActionCallback)`: Async decision creation
  - Generates unique decision ID using ThreadLocalRandom
  - Validates user authentication
  - Creates Decision object with current timestamp
  - Saves to Firestore with user ID
  - Triggers data change notification via callback

- `createDecision(String, String, String, long)`: Blocking decision creation
  - Same logic as async version but blocks until complete
  - Returns generated decision ID

- `hasSimilarDecision(String, String, long)`: Check for similar decisions
  - Searches for decisions with same title and category within 24 hours
  - Case-insensitive comparison

- `deleteDecision(long)`: Remove decision from Firestore
  - Uses await() for synchronous deletion

- `getAllDecisionRecords()`: Fetch all user's decisions
  - Queries Firestore filtered by user ID
  - Maps documents to DecisionRecord objects
  - Sorts by decision time (descending)

- `getDecisionRecord(long)`: Fetch single decision by ID
  - Validates user ownership
  - Returns null if not found or belongs to different user

#### Evaluation Management
- `saveEvaluation(long, String, String)`: Blocking evaluation save
  - Updates decision document with outcome, reflection, timestamp
  - Uses Firestore update operation

- `saveEvaluation(long, String, String, ActionCallback)`: Async evaluation save
  - Same logic as blocking version with callback
  - Triggers data change notification

#### Real-time Updates
- `listenToDecisions(DecisionRecordsListener)`: Set up Firestore snapshot listener
  - Filters documents by user ID
  - Returns LiveData through callback interface
  - Handles errors gracefully without clearing data
  - Automatically updates on remote changes

- `getDataChangedTrigger()`: LiveData for manual refresh triggers
  - Used by other components to trigger refreshes

#### Analytics
- `getAnalyticsSnapshot()`: Calculate comprehensive analytics
  - Counts decisions by outcome (good/bad/neutral)
  - Calculates category-based regret rates
  - Analyzes time-of-day patterns (Late night, Morning, Afternoon, Evening)
  - Generates textual insights based on patterns
  - Identifies worst categories and time periods

  **Analytics Logic**:
  ```java
  // Category regret rate calculation
  regretRate = (regretCount / evaluatedCount) * 100
  
  // Time bucket analysis
  - Late night: 23:00 - 05:00
  - Morning: 05:00 - 12:00
  - Afternoon: 12:00 - 17:00
  - Evening: 17:00 - 23:00
  
  // Generated insights examples
  - "You regret money decisions 45% of the time."
  - "Decisions made after 11PM are mostly bad (60% regret)."
  - "You have 5 decisions ready for review right now."
  ```

#### Helper Methods
- `mapDecisionRecords(QuerySnapshot)`: Convert Firestore documents to DecisionRecord objects
  - Handles null userId edge cases
  - Parses document ID to long
  - Builds DecisionRecord from Decision and optional Evaluation
  - Sorts by decision time descending

- `buildDecisionRecord(Decision)`: Combine Decision with Evaluation
  - Checks if decision is evaluated (outcome not null/empty)
  - Creates Evaluation object from decision properties
  - Returns DecisionRecord

- `requireUserId()`: Validate authentication
  - Throws IllegalStateException if user not logged in

- `await(Task<T>)`: Synchronous task wrapper
  - Uses Tasks.await() to block on Firebase operations
  - Converts ExecutionException to RuntimeException
  - Handles InterruptedException

- `decisionDocument(long)`: Get Firestore document reference
  - Returns DocumentReference for decisions collection

    if ("reviewed".equals(statusFilter)) return record.isEvaluated();

boolean matchesCategory(DecisionRecord record) {
    return "All".equals(categoryFilter) || 
           categoryFilter.equalsIgnoreCase(record.getDecision().getCategory());
}

## Notification System

### NotificationScheduler.java
Manages reminder notifications using Android AlarmManager.

**Key Methods**:
- `createNotificationChannel(Context)`: Setup Android O+ notification channel
  - Channel ID: "decision_review_channel"
  - Importance: DEFAULT
  - Only runs on Android O+

- `scheduleReminder(Context, long, String, long)`: Schedule alarm for evaluation time
  - Uses AlarmManager.RTC_WAKEUP
  - Allows while idle (setAndAllowWhileIdle)
  - Ensures trigger time is in future
  - Creates PendingIntent for broadcast

- `cancelReminder(Context, long)`: Cancel scheduled alarm
  - Uses AlarmManager.cancel()
  - Cancels PendingIntent with same request code

- `buildPendingIntent(Context, long, String)`: Create PendingIntent for broadcast
  - Intent targets EvaluationReminderReceiver
  - Includes decision ID and title as extras
  - Uses FLAG_UPDATE_CURRENT | FLAG_IMMUTABLE

- `toRequestCode(long)`: Convert decision ID to request code
  - Hash function: decisionId ^ (decisionId >>> 32)
  - Math.abs() to ensure positive
  - Used for PendingIntent uniqueness

### EvaluationReminderReceiver.java
Broadcast receiver that handles notification triggers.

**Key Methods**:
- `onReceive(Context, Intent)`: Handle alarm trigger
  - Creates notification channel
  - Checks POST_NOTIFICATIONS permission (Android 13+)
  - Extracts decision ID and title from intent
  - Creates notification with decision details
  - Sets pending intent to open DecisionDetailActivity
  - Shows notification

**Notification Details**:
- Small icon: android.R.drawable.ic_popup_reminder
- Auto-cancel: true
- Priority: DEFAULT
- Content intent: Opens DecisionDetailActivity with decision ID

### BootReceiver.java
Reschedules notifications after device reboot.

**Key Methods**:
- `onReceive(Context, Intent)`: Handle BOOT_COMPLETED
  - Fetches pending decisions from repository
  - Reschedules all reminders for pending decisions
  - Runs on background thread
  - Handles errors gracefully

**Purpose**: Ensures notifications persist across device reboots by rescheduling them when the device boots.

### ActivityScheduler.java
Manages periodic checks for missed activities using WorkManager.

**Key Methods**:
- `scheduleMissedActivityCheck(Context)`: Schedule periodic WorkManager task
  - Uses PeriodicWorkRequest with 15-minute interval
  - Sets minimal constraints (no battery/charging requirements)
  - Uses REPLACE policy to update existing work
  - Targets ActivityMissedWorker

- `cancelMissedActivityCheck(Context)`: Cancel periodic checks
  - Uses WorkManager.cancelUniqueWork()
  - Stops the periodic missed activity checking

**Purpose**: Automatically checks for missed activities at regular intervals to trigger pattern detection and recovery missions.

### ActivityMissedWorker.java
WorkManager worker that handles missed activity detection.

**Key Methods**:
- `doWork()`: Execute missed activity check
  - Queries ActivityRepository for missed activities
  - Triggers pattern detection if needed
  - Creates recovery missions when patterns detected
  - Returns Result.success() or Result.failure()

**Purpose**: Background task that periodically analyzes missed activities and initiates recovery mechanisms when concerning patterns are detected.

### PreMissReminderScheduler.java
Manages pre-miss reminders for activities (10 minutes before scheduled time).

**Key Methods**:
- `schedulePreMissReminder(Context, Activity)`: Schedule reminder before activity deadline
  - Uses AlarmManager.RTC_WAKEUP
  - Schedules for 10 minutes before scheduledTime
  - Creates PendingIntent for PreMissReminderReceiver
  - Uses setAndAllowWhileIdle for reliability

- `cancelPreMissReminder(Context, long)`: Cancel pre-miss reminder
  - Uses AlarmManager.cancel()
  - Cancels PendingIntent for specific activity ID

**Purpose**: Provides advance warning before activities are missed, giving users a chance to complete them on time.

### PreMissReminderReceiver.java
Broadcast receiver that handles pre-miss notification triggers.

**Key Methods**:
- `onReceive(Context, Intent)`: Handle pre-miss alarm trigger
  - Creates notification channel
  - Checks POST_NOTIFICATIONS permission (Android 13+)
  - Extracts activity ID and title from intent
  - Creates notification with activity details
  - Sets pending intent to open activity completion screen
  - Shows notification

**Notification Details**:
- Small icon: android.R.drawable.ic_popup_reminder
- Auto-cancel: true
- Priority: DEFAULT
- Content intent: Opens activity for completion

**Purpose**: Warns users 10 minutes before an activity deadline to prevent missed activities.

## Design Patterns

### 1. Repository Pattern
**Location**: `DecisionRepository.java`

**Purpose**: Centralized data access abstraction

**Implementation**:
- Single repository class for all decision-related data operations
- Abstracts Firebase Firestore complexity from ViewModels
- Provides both sync and async methods
- Handles authentication and user filtering internally

**Benefits**:
- Single source of truth for data operations
- Easy to swap data sources (Firestore → Room → API)
- Centralized error handling
- Testable business logic

### 2. MVVM Architecture
**Location**: All ViewModels and UI components

**Purpose**: Separation of UI and business logic

**Implementation**:
- **Model**: Data classes (Decision, Evaluation, etc.)
- **View**: Activities and Fragments
- **ViewModel**: Business logic and state management
- LiveData for reactive updates

**Benefits**:
- Testable business logic (ViewModels without UI)
- Survives configuration changes
- Clear separation of concerns
- Reactive UI updates

### 3. Observer Pattern
**Location**: LiveData throughout the app

**Purpose**: Reactive data updates

**Implementation**:
- ViewModel exposes LiveData for state
- UI observes LiveData and updates automatically
- Firestore snapshot listeners for real-time remote updates

**Benefits**:
- Automatic UI updates on data changes
- No manual refresh needed
- Lifecycle-aware (no memory leaks)

### 4. Callback Pattern
**Location**: Repository callbacks, AuthHelper callbacks

**Purpose**: Handle async operations

**Implementation**:
```java
interface ActionCallback {
    void onSuccess();
    void onError(String error);
}
```

**Benefits**:
- Handles async Firebase operations
- Provides success/error feedback
- Allows UI updates on completion

### 5. Singleton Pattern
**Location**: `AuthHelper.java`, `ThemeManager.java`

**Purpose**: Single instance for global operations

**Implementation**:
- Static methods only
- No public constructors
- Private constructors prevent instantiation

**Benefits**:
- Global access point
- Single instance ensures consistency
- Memory efficient

### 6. Builder Pattern
**Location**: `NotificationCompat.Builder`, `MaterialAlertDialogBuilder`

**Purpose**: Complex object construction

**Implementation**:
- Chainable method calls
- Fluent API
- Optional parameters

**Benefits**:
- Readable code
- Flexible object creation
- Handles complex construction logic

### 7. Factory Pattern
**Location**: `ViewModelProvider.AndroidViewModelFactory`

**Purpose**: Create ViewModel instances

**Implementation**:
- Factory creates ViewModels with Application context
- Handles ViewModel lifecycle

**Benefits**:
- Centralized creation logic
- Consistent instantiation
- Handles dependencies

### 8. Adapter Pattern
**Location**: RecyclerView adapters

**Purpose**: Adapt data for display

**Implementation**:
- `DecisionAdapter` adapts DecisionRecord to RecyclerView
- `InsightAdapter` adapts String insights to RecyclerView

**Benefits**:
- Separates data from display logic
- Reusable components
- Efficient list rendering

### 9. Strategy Pattern
**Location**: Date formatting strategies in `DateUtils`

**Purpose**: Different formatting algorithms

**Implementation**:
- Multiple format methods for different use cases
- Same input, different output based on strategy

**Benefits**:
- Flexible formatting
- Easy to add new formats
- Clear separation of strategies

## Data Flow Summary

### Unidirectional Data Flow
```
User Input
    ↓
Fragment/Activity
    ↓
ViewModel (Business Logic)
    ↓
Repository (Data Access)
    ↓
Firebase Firestore (Cloud Storage)
    ↓
Repository (Data Mapping)
    ↓
ViewModel (State Update)
    ↓
LiveData (Reactive Trigger)
    ↓
Fragment/Activity (UI Update)
```

### Real-time Data Flow
```
Firestore Remote Change
    ↓
Snapshot Listener
    ↓
Repository (Data Mapping)
    ↓
ViewModel (State Update)
    ↓
LiveData (Reactive Trigger)
    ↓
Fragment/Activity (UI Update)
```

### Key Principles
- **Data flows downward**: From repository to UI
- **Events flow upward**: From UI to repository
- **State is immutable**: New state objects created on changes
- **Reactive updates**: LiveData and snapshot listeners handle updates automatically
- **Single source of truth**: Repository is the only data access point
